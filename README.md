# Mail -> Telegram

Раз в минуту проверяет почтовый ящик по IMAP и присылает в Telegram: тему, отправителя, вложения и начало текста письма.
Письма в ящике остаются непрочитанными. Нужен только Python (уже стоит), ничего ставить не надо.
Когда компьютер выключен, ту же работу с задержкой делает GitHub Actions (см. ниже).

## Настройка (один раз, ~5 минут)

### 1. Создать бота
1. В Telegram открой **@BotFather** (с синей галочкой).
2. Отправь `/newbot`.
3. Имя бота: любое, например `Моя почта`.
4. Username: должен кончаться на `bot`, например `my_mail_alerts_bot`.
5. BotFather пришлёт токен вида `1234567890:AAH...`. Это пароль от бота, никому не показывай.
6. Открой `.env` в этой папке и впиши токен после `TELEGRAM_BOT_TOKEN=`.

### 2. Узнать свой chat_id
1. Найди своего бота в Telegram по username и нажми **Start** (или напиши ему что угодно).
2. В PowerShell:
   ```
   cd "путь\к\папке\mail-to-telegram"
   python mail_to_telegram.py --chat-id
   ```
3. Скрипт напечатает `chat_id = 123456789`. Впиши это число в `.env` после `TELEGRAM_CHAT_ID=`.

### 3. Пароль от почты
Впиши в `.env` после `IMAP_PASSWORD=` пароль, которым входишь на maimail.org. Отдельный пароль приложения не нужен.

### 4. Проверка
```
python mail_to_telegram.py --check
```
Должно напечатать `папка INBOX: OK` и прийти сообщение «Бот подключён к почте» в Telegram.

### 5. Запуск в фоне
```
Start-ScheduledTask -TaskName "Mail to Telegram"
```
Дальше бот сам запускается при каждом входе в Windows, без окна. Пришли себе тестовое письмо на maimail.org: через минуту оно появится в Telegram.

## Полезное

| Что | Команда / файл |
|---|---|
| Лог работы | `mail_to_telegram.log` |
| Остановить | `Stop-ScheduledTask -TaskName "Mail to Telegram"` |
| Запустить | `Start-ScheduledTask -TaskName "Mail to Telegram"` |
| Убрать автозапуск | `Unregister-ScheduledTask -TaskName "Mail to Telegram" -Confirm:$false` |
| Вернуть автозапуск | `powershell -ExecutionPolicy Bypass -File install_autostart.ps1` |
| Папки ящика | `python mail_to_telegram.py --folders` |

После правки `.env` перезапусти: Stop, потом Start.

**Следить ещё и за спамом.** Важное письмо может упасть в «СПАМ». Посмотри имя папки через `--folders` и допиши в `.env`, например `IMAP_FOLDERS=INBOX,Junk`.

**Сменить почту.** Поменяй в `.env` `IMAP_HOST`, `IMAP_PORT`, `IMAP_USER`, `IMAP_PASSWORD`, выполни `python mail_to_telegram.py --mark-all` (чтобы старые письма нового ящика не пришли разом), обнови секреты на GitHub (`gh secret set -f .env`) и перезапусти задачу. Примеры:
- Gmail: `imap.gmail.com`, `993`, нужен пароль приложения (Google аккаунт -> Безопасность -> Пароли приложений).
- Outlook/Hotmail: `outlook.office365.com`, `993`.
- Любой другой: в настройках почты ищи «IMAP», там будут сервер и порт.

## Когда компьютер выключен: GitHub Actions

Скрипт работает в двух местах сразу:

- **Компьютер** (задача в Планировщике): проверяет раз в минуту, шлёт сразу.
- **GitHub Actions** (`.github/workflows/check-mail.yml`): раз в 5 минут (по факту GitHub опаздывает, обычно 5-15 минут) шлёт только письма, которые лежат в ящике дольше 3 минут и ещё не отправлены. Пока компьютер включён, таких писем нет, и GitHub молчит.

Дублей нет, потому что «уже отправлено» хранится в самом ящике: после отправки на письмо ставится невидимая IMAP-метка `$TgNotified`. Письмо при этом остаётся непрочитанным. Уведомления от GitHub подписаны «через GitHub, компьютер был выключен».

Пароли для GitHub лежат в Settings -> Secrets and variables -> Actions репозитория. Залить их заново из `.env`: `gh secret set -f .env`. Запустить проверку вручную: вкладка Actions -> check-mail -> Run workflow. Выключить подстраховку: там же, `...` -> Disable workflow.

**Как это устроено.** Бот берёт письма без метки `$TgNotified`, пришедшие за последние 3 дня, отправляет в Telegram и ставит метку. Если Telegram недоступен, метка не ставится, и письмо уйдёт на следующем круге. Письма старше 3 дней не шлются никогда. Вторую копию на компьютере скрипт не запустит.
